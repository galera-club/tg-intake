# tg-intake (Предложка)

Telegram-бот, который связывает тех, кто ставит задачи, с теми, кто их делает.
Менеджер или заказчик описывает проблему как умеет: текстом, голосовыми,
скриншотами. Бот доводит это интервью до описания, с которым можно работать,
и заводит тикет в GitHub Issues нужного проекта.

Цель - убрать из процесса человека, который переводит сырой фидбек в постановку.
Автор рассказывает боту, что не так, и получает номер тикета; разработчик берёт
тикет и начинает работу без единого уточняющего вопроса. Тем же путём идут движение
тикета и вопросы по документации проекта; впереди заведение нового проекта
через интервью - порядок и границы в [docs/prd.md](docs/prd.md).

## Как это работает

1. Автор выбирает проект и нажимает «Создать тикет».
2. Накидывает контекст: текст, голосовые, скриншоты, ссылки. Бот копит и не
   перебивает.
3. Автор нажимает «Готово». Голосовые превращаются в транскрипт, затем
   скриншоты разбираются уже с учётом того, на что жалоба.
4. Бот добивает недостающее раундами по два-три вопроса, каждый с
   предполагаемым ответом. Кнопка «Всё так» принимает раунд целиком.
5. Бот показывает саммари и спрашивает, где ошибся; там же - пересечения с уже
   выпущенным и заведённым, если нашлись. После подтверждения публикует issue и
   отдаёт номер и ссылку.
6. Файлы удаляются, в базе и в тикете остаётся текст и `file_id` Telegram.
7. Позже автор смотрит тикеты проекта командой `/tickets`: список со статусами,
   карточка с телом, у закрытых - последний комментарий, отмена своего тикета.

Второй вход в проекте - «Спросить». Тот же сбор и то же «Готово», но вместо
тикета бот читает md-файлы репозитория и отвечает со ссылкой на источник; в
документации ответа нет - говорит прямо. Просьба о правке переводит разговор в
создание тикета, кнопка «Создать тикет» делает то же одним тапом.

Новый проект заводится одним сообщением: `/project <ссылка на репозиторий>`.
Бот читает репозиторий сам и показывает, что получилось.

## Стек

Go 1.25, PostgreSQL 16 (данные и очередь через `FOR UPDATE SKIP LOCKED`),
миграции goose, Telegram Bot API через `telebot.v4`, LLM через OpenRouter,
GitHub REST API. Runtime - один сервис в Docker, контур в Coolify.

## Запуск

Всё из каталога `src`, переменные - в `.env` по образцу `.env.example`.

```sh
cp .env.example .env
docker compose up -d postgres
make migrate-up
make run
make ci-check
```

Секреты передаются переменными окружения и в репозиторий не попадают:
токен Telegram-бота, ключ OpenRouter, GitHub PAT с правом Issues read/write,
белый список Telegram ID, строка подключения к базе.

## Ветки и релизы

Ветка одна - `prod`. Срез делается в `feature/<slug>`, идёт PR в `prod` и
после мерджа удаляется. Деплой - по команде владельца скриптом
`coolify-deploy.sh`; автодеплоя по push нет. История версий - [CHANGELOG.md](CHANGELOG.md).
